### 必须记住的协议要点（容易踩坑）
1. **两条编码路径不可混用**：
   - 17 段存储格式 = `MessageDecoder.encode(MessageExt, boolean)`，topic 长度固定 1 字节、魔数固定 v1。
   - 6 段轻量格式 = `MessageDecoder.encodeMessage(Message)`，MAGICCODE/BODYCRC 恒为 0、**不含 topic**，
     只用于批量消息 body。
   - V2 魔数（-626843477，topic 长度 2 字节）只在 **decode 侧**存在，Java encode 不会写 V2。
2. **发送请求的 body 语义**（`MQClientAPIImpl.sendMessage` 第 562~567 行）：
   普通消息 = `msg.getBody()` 原始字节；批量消息 = `MessageBatch.encode()`（
   `DefaultMQProducer.batch` 里 `msgBatch.setBody(msgBatch.encode())`）。
   曾经误做成"发送也走 17 段编码"，已修正。
3. `UtilAll.bytes2string` 产出**大写**十六进制（HEX_ARRAY = "0123456789ABCDEF"），
   这直接决定 msgId 的表示；`string2bytes` 是 hex 解码，不是 utf-8 编码。
4. `MessageSysFlag`（develop 分支）：COMPRESSED=bit0，MULTI_TAGS=bit1，事务 =bit2~3，
   BORNHOST_V6=bit4，STOREHOST_V6=bit5，NEED_UNWRAP=bit6，INNER_BATCH=bit7，
   压缩类型在 **bit8~10**，掩码 `0x7<<8`，`getCompressionType = (flag & 0x700) >> 8`。
5. `MessageQueue.hashCode` 必须按 32 位有符号回绕：`((31+bh)*31+qid)*31+th`。
6. 属性串解析与 Java 一致：长度 < 3 或无 kv 分隔符的片段会被丢弃，**空 value 的属性会丢失**。
7. RemotingCommand 帧：`totalLen(4) | headerLen(4，高 8 位序列化类型) | header | body`，
   `totalLen = 4 + len(header) + len(body)`；flag bit0 = 响应，bit1 = oneway。
8. `SendMessageRequestHeaderV2` 短字段名 a..n（n = brokerName）。
