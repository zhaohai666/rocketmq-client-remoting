## 用户问：三客户端 vs Java 还有哪些不足？

直接回答（未新写代码）。结论：P0/P1 消费侧差距已全部关闭并推送到 origin/main（Python 21/0、
C++ 17/0、.NET 17/0）。剩余差距按严重度：

- **P1（生产硬伤）**：命名空间包裹、ACL 鉴权 —— 仅 Python 有，C++/.NET 都没有（grep 验证：
  `namespace_util`/`AclRPCHook` 只在 python/，cpp/dotnet 的命中只在 admin 代码）。
- **P2**：主动拉取 PullConsumer（仅 Python）、故障规避 sendLatencyFaultEnable、POP 模式(5.x)、
  Request-Reply(5.x) —— 三侧均缺（后两者仅常量）。
- **P3**：消息轨迹 Trace/Hook、TLS、动态 name server、客户端统计、其它 broker 主动请求(307 等)、
  细粒度流控/消费线程弹性 —— 三侧均缺。

已把完整差距表写进 MEMORY.md「与 Java 客户端仍存在的差距」一节，建议下一步优先补 C++/.NET 的
namespace + ACL（照搬 Python 实现）。
